# Contributing to XIS Unified

## Working principles

1. Preserve existing behaviour unless a change is explicitly intended.
2. Inspect the current implementation before rebuilding a feature.
3. Keep changes small and explain why they are needed.
4. Add or update tests for changed behaviour when the project supports tests.
5. Document setup, configuration, and any migration steps.
6. Never commit credentials, private keys, tokens, personal data, or production `.env` files.

## Before opening a pull request

- [ ] Describe the problem and proposed change.
- [ ] List the files or modules changed.
- [ ] Run relevant tests and report the actual result.
- [ ] State any untested areas and known limitations.
- [ ] Update documentation when behaviour or setup changes.
